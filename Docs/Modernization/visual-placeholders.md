# Unity-created visual placeholders

Restored 29 missing material GUIDs and one unambiguous missing mesh GUID with real native assets generated by Unity 6000.3.26f1. The assets live under `Assets/Art/ModernizationPlaceholders`; filenames and native object names include `PLACEHOLDER`. They provide visible temporary content, not recovered original artwork.

Materials use the actual public URP 17.3.0 Unlit shader and a bright deterministic color derived from each original GUID. All 85 original references to these material GUIDs use native material `fileID: 2100000, type: 2`. Unity's `AssetDatabase.TryGetGUIDAndLocalFileIdentifier` verified each generated material's original GUID, native file ID and actual Material type after import.

The one mesh uses Unity's unit cube geometry (24 vertices, 36 triangle indices). Its original GUID is `6d6cd06c2176aab46a6da9dd4e1f83e9`; it was referenced only by the MeshFilter and MeshCollider in `Art/Prefabs/Environment/Props/SM_Tree_Stump_01.prefab`, both with file ID 4300000. Shape, collision and appearance differ from the removed tree-stump mesh and require gameplay/art review before release.

## Actual reference validation

Generation ran in an isolated `.local/visual-placeholder-project` with public URP and Unity's physics module, without game SDKs or compatibility stubs. Unity created and serialized the materials/mesh and their importer metadata. The only manual metadata edit replaced Unity's new GUID with the already-referenced original GUID; Unity then imported and validated the native type/GUID/file ID. No asset YAML schema or prefab hierarchy was invented.

An initial actual import of the original stump prefab failed to resolve its mesh because the original pointers were `type: 3` imported-model references, while the replacement is a native asset. Retaining only its GUID/file ID would have produced a false-positive static audit. The next run assigned the actual native mesh to the original MeshFilter and MeshCollider through Unity's object API and saved the existing prefab with PrefabUtility. Unity wrote the required `type: 2` pointers and seven current renderer defaults. All five original object/component local IDs stayed identical, and the original project prefab's `.meta` was preserved.

The successful run then loaded the actual prefab and verified that its MeshFilter and MeshCollider resolved the same replacement mesh, and its MeshRenderer resolved replacement material `9815abc3682332c43bb766decd901afb` with the correct original GUID/file ID and URP shader. The 30 copied native assets and their metadata were checked byte-for-byte against the Unity-validated scratch outputs.

This is actual import/reference evidence for the generated native assets and the stump prefab. It does not establish complete scene rendering, Addressables success or a playable match. No screenshot/render or player build was produced by this work.

## Audit reduction and exclusions

The original audit counted Unity's actual built-in resource GUIDs as missing. Root corrected that filter. To compare like with like, both snapshots below exclude the actual built-in `0000000000000000e000000000000000` / `0000000000000000f000000000000000` resource GUIDs.

| Measure | Before placeholders | After placeholders | Attributable reduction |
| --- | ---: | ---: | ---: |
| Unresolved reference rows | 153,464 | 153,377 | 87 |
| Unique unresolved GUIDs | 1,429 | 1,399 | 30 |
| Unresolved script references | 18,308 | 18,308 | 0 |

The 87 restored rows comprise 85 material references across 31 source files and the two stump mesh references. Every restored GUID disappeared from the unresolved CSV. This count is a narrowly classified subset; missing prefab hierarchies, scripts, rigged meshes and other deleted content remain unresolved.

Of 62 missing-GUID mesh candidates from the initial raw scan, only the stump satisfied the native file ID and MeshFilter/Collider requirements. Excluded the other 61: 58 imported-model/subasset ID sets whose native IDs could not be reproduced safely, two particle-system mesh references outside the requested scope, and one built-in resource false positive. No arbitrary local file IDs, source-model names or missing prefab hierarchies were guessed.
